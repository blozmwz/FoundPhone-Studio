# 1505 / stage123-20261102-r3：旧存档黑屏紧急修复

本轮只修存档读取、迁移和备份，不改剧情或素材。公开范围仍为 Stage 1—3。部署目标：Cloudflare Pages `bdg`，`blozmwz/FoundPhone-Studio` 的 `main`，https://bdg-bp3.pages.dev/ 。

## 已复现的具体原因

1503/1504 的 `RoommateMessages` 视频按钮执行 `onRead(thread)`，传入 `Hendery` 或 `Yuki`。这两个是会话标题，不是剧情记录 ID。引擎把它们加入 `state.read`。同版本读取原来跳过节点校验，因此错误记录可以一直潜伏；更新版本后 `validateSaveAnchors` 找不到这两个 ID，抛出截图中的黑屏提示。

用真正的 1503 构建点击该按钮、导出数据库，再加载到 1504，已分别复现 Yuki 和 Hendery 两种情况，旧数据库原样保留。此原因不依赖 Threads 浏览器。尚未收到截图玩家本人的导出档，不能断言所有同提示存档都只有这一原因。

## 明确映射与保护

- 仅将不存在于故事记录中的 `read` 标记 `Hendery`、`Yuki` 移到 `ui.compatibility.legacyConversationReads`；真正的消息已读、姓名、已发送内容、分支和完成记录保留。
- 退役 `life-topic-movie:*`、`life-topic-food:*`、`life-topic-small:*`：移除尚未发送的旧入口、该话题的待发任务，保留已经发生的历史，归档旧草稿并保留待进入的主线日期。不把草稿当作已经发送。
- `public-demo-ending-1/2`：仅旧入住试玩停点回接 `scene-viewing-contract`；真实拒绝结局不改。已有版本专用迁移仍负责后续日期，Stage 2 末尾接入 12月4日。
- 无法识别的节点仍阻断，抛出可检查的 `SaveAnchorError.details`，不清空、不跳过版本/作品/结构校验。即使同版本也校验。
- 视频通话入口禁用（原本无可用视频功能），读取事件入口校验记录 ID，防止继续制造假已读记录。

迁移顺序：读取当前槽/即时日志 → 原样备份 → 纯函数迁移 → 完整校验 → 数据库事务提交 → 才进入游戏。备份失败、校验失败、提交失败或另一个页面已改动进度，均保留旧当前槽和即时日志。

数据库仍是 `foundphone-studio` / `saves`，版本仍为1。原始备份使用带原版本、目标版本和内容摘要的独立行，已有原件不覆盖；`:before-migration` 仅指向最近原件。设置 → 游戏进度 →「导出更新前存档」可下载原件。导入旧档也保留导入原件。自动存档/正常槽 ID 不变，玩家无需主动迁移或清缓存。
